# YAPP Coding Conventions

[AGENTS.md](../../../AGENTS.md)의 작업 범위·자동화 정책과
[.editorconfig](../../../.editorconfig)의 서식을 따른다.
변경 파일과 호출부를 읽고 기존 수정 사항을 보존한다.

## 파일과 가시성

- 패키지 루트는 `com.yapp.plus`다. 모듈별 패키지는
  [yapp-module-structure](../yapp-module-structure/SKILL.md)를 따른다.
- 파일당 클래스·인터페이스는 하나다. sealed 타입과 관련 하위 타입은 같은 파일에 둘 수 있다.
- `private` 클래스는 만들지 않는다. 이 금지는 클래스에 적용한다.
- 확장 함수는 허용한다. 변환·동작의 책임과 모듈 의존성 경계를 지킨다.

## 함수와 제어 흐름

- `if`·`when`·반복문 같은 제어문의 중첩 깊이는 최대 2단계다.
  초과하면 조기 반환이나 책임이 드러나는 함수 분리로 줄인다.
- 함수가 15줄을 넘으면 분리를 검토한다. 서로 다른 책임이 있으면 나눈다.
  15줄은 검토 기준이며 길이만 맞추기 위한 분리는 하지 않는다.
- 상태 변경·데이터 호출·결과 처리가 서로 다른 책임이면 각각 분리한다.
- 복잡한 다중 분기는 `when`, 단순 조건 검사와 조기 반환은 `if`를 사용한다.
- 값 변환·필터링은 `map`·`filter`를 사용한다.
- 상태 변경·데이터 저장·가변 값 누적이 있는 반복은 `for`로 실행 흐름을 드러낸다.

## 서식

- 들여쓰기 4칸, UTF-8, LF와 파일 마지막 개행을 사용한다.
- Kotlin·Gradle Kotlin 코드는 한 줄 최대 100자다. 긴 선언·호출·표현식은 줄바꿈한다.
- 함수 선언의 매개변수가 2개 이상이면 한 줄에 하나씩 쓰고 마지막에도 쉼표를 붙인다.
- Boolean이나 같은 타입의 인자가 연속되면 이름 있는 인자를 사용한다.
  복잡한 Composable·Canvas 호출도 이름 있는 인자를 사용한다.
- 여러 Modifier를 연결하면 한 줄에 하나씩 쓴다.

```kotlin
fun submitAttendance(
    sessionId: String,
    attendanceCode: String,
) {
    // 확인된 출석 정책을 처리한다.
}
```

## 이름과 도메인 표현

- `cnt`, `usrId` 같은 축약어 대신 의미가 드러나는 이름을 사용한다.
- 조회 함수는 `fetch`·`find`·`search`, 변경 함수는 `update`·`change`·`save`처럼 동작을 표현한다.
  기존 API를 구현·재정의할 때는 해당 계약을 따른다.
- Boolean 이름은 `is`·`has`·`can`·`should`를 사용한다.
- 수치는 `elapsedMs`, `remainingRatio`, `retryCount`처럼 의미와 단위를 드러낸다.
- 의미 있는 고정 숫자와 반복 문자열은 이름 있는 상수로 추출한다.
- 식별자·검증 규칙이 있는 값은 value class를 검토한다.
- 컬렉션에 자체 규칙·행동이 있으면 별도 타입으로 캡슐화한다.
  모든 값·컬렉션에 래퍼를 일괄 적용하지 않는다.
- 주석은 코드만으로 드러나지 않는 의도·제약·선택 이유를 설명한다.

## UI 리소스와 정보 관리

- 사용자에게 표시하는 문구는 `strings.xml`에서 관리한다.
  값 삽입에는 `%1$s`, `%2$d` 같은 위치 지정 placeholder를 사용한다.
- 공통 텍스트·버튼·색상·타이포그래피는 `core:designsystem`에서 제공한다.
  반복되는 변형은 공통 컴포넌트의 variant로 추가한다.
- API 키·서명 정보·개인 로컬 설정을 커밋하지 않는다.

## 완료 확인

- 업무 규칙·상태 전이·매핑·오류 처리처럼 실패 위험이 있는 동작을 검증한다.
  기존 테스트 도구부터 사용하고 표현을 그대로 반복하는 테스트는 추가하지 않는다.
- 변경 모듈과 영향받는 호출부를 우선 검증하고 필요한 경우 범위를 확대한다.
- 실제 실행한 명령·결과·남은 실패를 보고하고 코드 문제와 환경 문제를 구분한다.
- 이 저장소에는 아직 포맷터·정적 분석 플러그인이 없다.
  도구 도입은 별도로 결정하고, 존재하지 않는 검사 명령을 실행했다고 보고하지 않는다.
