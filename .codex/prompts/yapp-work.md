YAPP 작업 요청: $ARGUMENTS

이 명령을 직접 호출한 것은 계획·구현에 모델 지정 서브에이전트를 순서대로 사용하는 명시적 요청입니다. 이 opt-in 명령 밖의 작업에 모델 분리나 서브에이전트 사용을 자동 적용하지 않습니다.

## 계획 단계

1. Codex 협업 도구 `spawn_agent`로 계획 서브에이전트를 시작하고 `model: "gpt-6-astra"`, `reasoning_effort: "max"`를 지정합니다.
2. 계획 서브에이전트에 읽기 전용 작업임을 명시합니다. 요청과 완료 기준, 관련 이슈·PR, 현재 브랜치와 diff, 실제 구현·모듈, 관련 Wiki·스킬, 영역 라벨과 PR 변경량을 조사하게 합니다. 파일 작성·수정, 브랜치 변경, 이슈·PR 작성, 커밋·푸시를 금지합니다.
3. 계획에는 목표와 범위, 변경 파일·모듈, 공개 계약과 의존 순서, 실패·경계 시나리오, 검증 명령, 필요한 이슈·브랜치, PR 영역·분리와 800줄 제한, 남은 가정·질문을 포함합니다. 제품 정책이나 API 계약이 없으면 추측하지 말고 사용자에게 물을 질문을 반환하게 합니다.
4. 조율자는 계획을 사용자에게 보여주고 명시적 승인을 기다립니다. 사용자가 계획을 수정하면 Astra 계획 서브에이전트로 계획만 갱신하고 다시 승인을 기다립니다. 침묵, 단순 질문, 모호한 답변을 승인으로 간주하지 않습니다. 조사·설계 전용 요청이면 구현 단계 없이 결과를 보고합니다.

계획을 제시한 뒤에는 멈춥니다. 사용자 승인 전에는 작업 트리나 GitHub를 변경하거나 구현 에이전트를 시작하지 않습니다.

## 승인 후 구현 단계

1. 사용자가 제시된 계획을 명확히 승인한 뒤 현재 작업 트리와 사용자가 추가한 변경을 다시 확인합니다. 프로젝트 지침에 따라 중복 이슈를 확인해 기존 이슈를 연결하거나 필요한 이슈를 만들고, 최신 기준 브랜치에서 작업 브랜치를 준비합니다. 기존 변경을 보존합니다.
2. 계획이 승인된 범위 안에 있는지 확인한 뒤 `spawn_agent`로 구현 서브에이전트를 시작하고 `model: "gpt-6.1-sol"`, `reasoning_effort: "max"`를 지정합니다. 원 요청, 승인된 계획, 이슈·브랜치, 담당 파일·모듈, 계약, 완료 기준, 검증 명령, 관련 프로젝트 스킬·Wiki를 전달합니다.
3. 구현 에이전트는 할당된 범위만 구현하고 적절한 검증을 실행합니다. 기존 변경을 되돌리거나 덮어쓰지 않습니다. 필수 정보가 없거나 작업 범위가 바뀌면 추측하지 말고 중단해 조율자에게 알립니다. Astra 계획과 6.1 SOL 구현은 직렬로 진행하며 구현 파일을 편집하는 작업자를 병렬 실행하지 않습니다.
4. 조율자가 결과를 통합하고 전체 diff를 리뷰합니다. 프로젝트 지침에 따라 Wiki 검사, 관련 테스트·빌드, `git diff --check`, PR 영역과 800줄 한도를 확인한 뒤 커밋·푸시·PR 생성 또는 기존 PR 갱신을 마무리합니다. 병합은 하지 않습니다.

완료 보고에는 이슈·PR 링크, 브랜치, 변경 내용과 줄 수, 실제 검증 결과, 미검증 항목과 남은 후속 작업을 포함합니다.
