# 코딩 컨벤션

Kotlin·Gradle Kotlin 코드에 적용합니다. 기계가 읽는 서식은 [.editorconfig](../../.editorconfig)를 함께 확인합니다. 패키지 배치는 [모듈 구조](module-structure.md)를 따릅니다.

## 파일과 가시성

- 패키지 루트는 `com.yapp.plus`입니다.
- 파일당 클래스·인터페이스는 하나입니다. sealed 타입과 관련 하위 타입은 같은 파일에 둘 수 있습니다.
- `private` 클래스는 만들지 않습니다. 확장 함수는 허용하되 책임과 모듈 의존성 경계를 지킵니다.

## 함수와 제어 흐름

- `if`·`when`·반복문 같은 제어문 중첩은 최대 2단계입니다. 초과하면 조기 반환이나 책임이 드러나는 함수로 분리합니다.
- 함수가 15줄을 넘으면 분리를 검토합니다. 서로 다른 책임이 있으면 나눕니다. 길이만 맞추기 위한 분리는 하지 않습니다.
- 상태 변경, 데이터 호출, 결과 처리가 서로 다른 책임이면 각각 분리합니다.
- 복잡한 다중 분기는 `when`, 단순 조건 검사와 조기 반환은 `if`를 사용합니다.
- 값 변환·필터링은 `map`·`filter`, 상태 변경·저장·가변 값 누적이 있는 반복은 `for`로 실행 흐름을 드러냅니다.

## 서식

- 들여쓰기 4칸, UTF-8, LF, 파일 마지막 개행을 사용합니다. Kotlin·Gradle Kotlin 코드는 한 줄 최대 100자입니다.
- 함수 선언의 매개변수가 2개 이상이면 한 줄에 하나씩 쓰고 마지막에도 쉼표를 붙입니다.
- Boolean이나 같은 타입의 인자가 연속되면 이름 있는 인자를 사용합니다. 복잡한 Composable·Canvas 호출에도 이름 있는 인자를 사용합니다.
- 여러 Modifier를 연결하면 한 줄에 하나씩 씁니다.

## 이름과 도메인 표현

- `cnt`, `usrId` 같은 축약어 대신 의미가 드러나는 이름을 사용합니다.
- 조회 함수는 `fetch`·`find`·`search`, 변경 함수는 `update`·`change`·`save`처럼 동작을 표현합니다. 기존 API 구현·재정의는 해당 계약을 따릅니다.
- Boolean 이름은 `is`·`has`·`can`·`should`를 사용합니다.
- 수치는 `elapsedMs`, `remainingRatio`, `retryCount`처럼 의미와 단위를 드러냅니다.
- 의미 있는 고정 숫자와 반복 문자열은 이름 있는 상수로 추출합니다.
- 식별자·검증 규칙이 있는 값은 value class를 검토합니다. 컬렉션에 자체 규칙·행동이 있으면 별도 타입으로 캡슐화합니다. 모든 값에 래퍼를 일괄 적용하지 않습니다.
- 주석은 코드만으로 드러나지 않는 의도·제약·선택 이유를 설명합니다.

## UI 리소스와 정보 관리

- 사용자 문구는 `strings.xml`에서 관리합니다. 값 삽입에는 `%1$s`, `%2$d` 같은 위치 지정 placeholder를 사용합니다.
- 공통 텍스트·버튼·색상·타이포그래피는 `:core:designsystem`에서 제공하고 반복되는 변형은 공통 컴포넌트의 variant로 추가합니다.
- API 키, 서명 정보, 개인 로컬 설정을 커밋하지 않습니다.

업무 규칙, 상태 전이, 매핑, 오류 처리처럼 실패 위험이 있는 동작을 검증합니다. 기존 도구를 사용하고 표현을 그대로 반복하는 테스트는 추가하지 않습니다. 실제 실행한 명령·결과·남은 실패를 보고합니다. 포맷터와 정적 분석 플러그인은 아직 선택하지 않았습니다.
