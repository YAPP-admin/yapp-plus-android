# 지식 후보함

작업 중 발견한 재사용 가능한 판단을 공식 정책과 분리해 둡니다. [후보 양식](../templates/knowledge-candidate.md)으로 한 후보당 한 파일을 작성합니다. 참고 자료는 후보의 근거에 연결합니다. 후보의 `authority: none`은 공식 정책의 근거가 아님을 뜻합니다.

## 승격 흐름

1. 먼저 [Wiki 목차](../README.md), 코드, 테스트, 승인된 요구사항과 비교합니다. 이미 있는 내용은 새 후보를 만들지 않고 해당 문서를 갱신합니다.
2. 아직 공식화할 근거가 부족하지만 재사용할 가치가 있으면 후보를 기록합니다. 단순 검색·열람은 사용 이력에 넣지 않습니다. 서로 다른 작업의 계획·구현·테스트·리뷰에서 판단 근거로 실제 적용했을 때만 작업당 한 번 기록합니다.
3. 제품 정책·사용자 흐름·데이터 안전 규칙은 사용 횟수와 관계없이 즉시 승격을 검토할 수 있습니다. 일반 후보는 서로 다른 작업에서 2회 이상 사용되면 승격을 검토합니다. 횟수는 검토 신호일 뿐 자동 승인이나 자동 승격이 아닙니다.
4. 승격할 때는 기존 문서와 중복·충돌을 확인하고, 확정된 의미만 해당 분야 문서에 반영합니다. 후보에 `status: promoted`, 사유, 대상 문서 경로를 남기고 [결정 기록](../decisions.md)을 추가합니다. 기각할 때는 `status: rejected`와 사유를 남깁니다.
5. 정책의 새 의미는 사용자 확정이 필요합니다. 이미 확정된 정책은 후보함을 거치지 않고 바로 분야별 문서와 결정 기록을 고칩니다. 코드·테스트에서 발견한 사실은 검증된 범위만 기록합니다.
