# 제품 정책

앱 동작은 확인된 제품 요구사항과 API 계약을 기준으로 정합니다. 화면이 표시하는 진행·예상 상태와 서버가 확정한 출석 결과를 구분합니다. YAPP의 2026 출석 규칙을 확인했으며, 출석 코드 검증·사전 출결 보고는 확인된 서버 계약으로 호출합니다. 실제 판정·점수 계산은 서버가 담당합니다. 홈의 이번 주 세션 요약과 일정 화면은 세션 조회 API를 표시합니다. My 출석 점수·이력은 사용자 API에 연결했습니다. 공지 목록·상세·읽음과 인증 응답의 이름을 연결했습니다. My 본인 프로필을 조회하고 실패 시 세션 이름을 표시합니다. 이용 문의는 YAPP 카카오톡 채널을 엽니다. 지각 면제권은 Figma UI를 유지하며 API 계약 확인을 기다립니다. 알림 설정은 현재 기기의 수신 선택을 저장하고 푸시 기기 등록·해제 API에 연결합니다.

- **세션·출석:** 홈 출석 동작은 세션 전·출석 오픈 전·출석 가능·출석 완료 상태를 구분합니다. 정규 세션은 시작 20분 전부터 4자리 코드로 출석하고 정상 출석·지각에 같은 완료 화면을 씁니다. 팀 세션은 사진과 참석 팀원을 제출하고 운영진 검수 결과에 따라 출석·결석·재제출 상태를 보여 줍니다. 사전 보고는 지각·조퇴·결석과 30자 이내 사유를 받으며, 모든 사전 보고는 세션 시작 전까지 받습니다. 결석 감점 인정의 48시간 기준과 접수 마감은 구분합니다.
- **홈·일정·게시판:** 홈은 이번 주 세션과 상태별 출석 동작, 최대 3개의 이번 주 공지를 표시합니다. 일정은 날짜순 세션·장소·시간·유형을 보여 주고 지난 일정은 흐리게 표시합니다. 미정 장소는 `-`로 표시하며 장소를 눌러 지도 앱으로 이동하지 않습니다. 게시판은 전체·세션·과제·기타 유형을 최신순으로 제공하고, 과제 마감 정보와 최대 5개 첨부 이미지, 읽음 확인을 지원합니다.

**현재 구현 상태:** 개발 앱은 YAPP 서버의 Google 인증·가입, 세션·출석 인증·사전 보고, 공지 목록·상세·읽음 API를 사용합니다. My는 본인 프로필과 출석 점수·이력을 표시합니다. 팀 사진 업로드·제출과 푸시 기기 등록·해제는 Domain·Data·App 조립까지 구현했습니다. ## 개발과 비공개 테스트 배포

- `release/v1.0.1`은 기존 비공개 테스트 버전을 보존합니다. 실제 서비스 개발은 `develop` 기반 작업 브랜치에서 진행합니다.
- Release 빌드는 같은 Google Play 앱, `applicationId` `com.yapp.plus`, 런처 이름 `YAPP+`를 사용하고 비공개 테스트 트랙으로 배포합니다. Debug 빌드는 `com.yapp.plus.debug`와 `YAPP+ (Debug)`를 사용해 Release와 같은 기기에 설치할 수 있습니다.
- 임시 테스트 브랜치를 실제 개발 브랜치에 통째로 병합하지 않습니다. 필요한 수정만 검토해 반영하고, 실제 서비스의 배포 후보는 최신 `develop`에서 새 릴리즈 브랜치로 준비합니다.
- 임시 테스트 전용 백엔드 구현·SQL·문서는 개발 버전에서 제거합니다. 기존 배포의 외부 서비스와 데이터는 유지합니다.

## 회원가입과 승인

서버는 `POST /api/users`에서 계정과 세션을 생성하면서 기수 멤버십 자동 승인 여부를 결정합니다. [백엔드 가입 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/c7685e86a9c6d2514ab158444a1f4812de57d919/APIDOC.md#8-user-가입-완료)

- 한국 날짜 기준(Asia/Seoul)으로 활동 중인 기수가 하나일 때 해당 기수의 `AVAILABLE` 사전 등록 명단을 확인합니다. 이름의 앞뒤 공백을 제외하고 정규화한 E.164 전화번호와 함께 비교합니다. 두 값이 일치하고 명단의 직군·역할이 유효하면 즉시 자동 승인합니다. 명단의 기수·직군·회원 구분을 소속에 반영하고 일치한 명단 항목을 `MATCHED`로 변경합니다.
- 자동 승인 조건을 충족하지 않으면 `PENDING`으로 가입합니다. 운영진은 백오피스에서 수동으로 승인하거나 거절할 수 있습니다. 이후 명단이 등록돼도 기존 대기 계정에 자동 승인을 소급 적용하지 않습니다.
- 두 경우 모두 가입 성공 시 승인 상태 없이 `200 OK`와 `SIGNED_IN` 세션을 반환합니다. Android는 공통 가입 완료 화면을 사용합니다. 별도 승인 대기 화면과 대기 상태 복원은 Android 가입 범위에서 제외합니다.

## 로그인·가입 구현 범위

개발 앱은 Google Credential Manager의 서버 Client ID에 Web Client ID를 사용합니다. 매 요청마다 원본 nonce를 만들고 그 SHA-256 소문자 hex를 Google 요청에 넣은 뒤, 받은 ID Token과 원본 nonce를 `POST /api/auth/oidc/google/native-authentications`에 보냅니다. Google Client Secret은 클라이언트에 포함하지 않습니다. ID Token·원본 nonce는 메모리에서만 전달하고 저장하거나 로그로 남기지 않습니다.

Google 인증의 `SIGNED_IN` 응답은 access/refresh token 쌍을 암호화 저장하고 메인으로 이동합니다. `SIGNUP_REQUIRED` 응답의 일회용 registration token은 App 메모리에만 두고 가입 화면으로 전달합니다. 가입은 `POST /api/users`에 registration token·이름·E.164 전화번호를 보냅니다. 성공 응답의 세션을 저장하고 가입 완료 화면을 거쳐 메인으로 이동합니다. 앱 시작 때 저장 세션을 복원해 메인 또는 로그인 화면을 선택합니다. 로그인 실패는 재시도할 수 있고, 가입 실패는 입력을 유지하며 응답 코드에 맞춰 재시도 또는 다시 로그인할 수 있습니다.

가입 이름·휴대폰 입력은 `:feature:signup`에서 관리하고 복원합니다. 한국 휴대폰 번호는 E.164 형식으로 변환해 보냅니다. registration token은 Navigation 인자나 `SavedStateHandle`에 저장하지 않으며, 프로세스 종료 후 유실되면 Google 로그인을 다시 진행합니다. 과거 완료 단계가 저장돼 있어도 휴대폰 입력으로 복원합니다.

가입 입력 오류는 `fieldErrors`의 `field`와 `code`로 구분하고 입력창에 표시합니다. 이름만 오류이면 이름 입력으로 돌아가며 전화번호를 유지합니다. 이름을 수정하면 전화번호 입력을 다시 받지 않고 기존 번호와 가입 토큰으로 재제출합니다. 두 입력 모두 오류이면 이름을 먼저 수정한 뒤 보관된 전화번호를 표시하고 번호도 수정합니다. 전화번호 중복은 전화번호 입력 오류로 처리하며, 필드 오류가 없는 인증·서버 오류는 기존 팝업으로 처리합니다. 이름 검증은 필수·형식·최대 100자 조건이며 실명·명단 일치 검증을 뜻하지 않습니다. [API 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/dev/APIDOC.md#8-user-가입-완료)을 따릅니다.

| 알림함 | `GET /api/users/me/notifications`. 목록·당겨서 새로고침·다음 페이지를 제공하고 공지 알림에서 상세로 이동합니다. |
| 통합 탈퇴 | `DELETE /api/users/me`; Bearer access token으로 요청하고 성공 응답 뒤 로컬 token 쌍을 삭제해 로그인 화면으로 이동. 실패하면 세션을 유지하고 다시 시도. Figma 확인·요청 진행·오류와 App 연결 구현 |

저장된 YAPP 토큰 쌍은 앱 시작과 첫 인증 API 요청 전에 복원합니다. 초기 Google 세션 발급은 YAPP API 계약에 연결했습니다. 로컬 access-token 주입이나 가짜 인증 세션은 만들지 않습니다.

## 수정된 홈 화면과 연결 흐름

YAPP 서버의 출석 인증·보고 계약을 따르며 홈에서 코드 출석과 사전 보고를 연결합니다.

- 기준은 사용자가 변경을 확정한 [Figma 홈 섹션](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=222-40284)과 [이슈 #82](https://github.com/YAPP-admin/yapp-plus-android/issues/82)입니다. 홈 메인·알림·출석 코드 입력/완료·출결 보고 화면까지 적용합니다.
- 홈은 이번 주 세션의 장소·제목, 일요일부터 토요일까지의 달력, 출석 상태와 빠른 메뉴, 이번 주 공지를 표시합니다. 오늘은 원형으로, 세션 날짜는 브랜드 색상으로 구분합니다. 서버의 `AVAILABLE` 상태에서만 출석 버튼을 활성화합니다.
- 홈의 팀 세션 카드 제목은 이번 주 세션 조회 응답의 `session.name`을 넣어 `이번 주는 … 세션이에요`로 표시합니다.
- 4자리 숫자 입력은 붙여넣기와 숫자 키보드를 지원합니다. 입력 형식 검증 뒤 `POST /api/attendance-verifications`에 `sessionId`와 정수 `code`를 전달합니다. `verified=true`와 유효한 `checkedInAt`을 받은 뒤 완료 화면을 열고 해당 세션 카드에 인증 완료를 반영합니다.
- 홈에 처음 진입하거나 복귀해 다시 조회하면 `current-week.attendanceStatus`의 현재 값을 표시합니다. 정규 세션의 `CHECKED_IN`은 달력의 세션 날짜에 `출석` 배지와 회색 비활성 `출석했어요!` 버튼을 표시합니다. `PENDING_APPROVAL`은 선택된 팀원의 사진 심사를 기다리는 “출석 확인 중이에요”를 표시합니다. 두 상태에서는 코드를 입력할 수 없습니다. `CHECKED_IN`은 인증 완료이며 최종 출결과 점수는 각 사용자 조회 API를 따릅니다. [Figma 출석 후 홈](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=418-18070) · [이번 주 세션 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/0f2ddbdf0c9aa6a8b754225d9c6938ab70097322/APIDOC.md#L312-L322)
- 지각·조퇴·결석 사전 보고는 [필수 사유 검증](#사전-보고-사유-검증)을 거칩니다. `POST /api/attendance-reports`에 유형과 사유를 보내고, 응답의 `sessionId`와 `submittedAt`을 확인한 뒤 완료 안내를 표시합니다.
- 홈의 이번 주 공지는 한국 시간의 일요일 00:00부터 다음 일요일 전까지의 게시 시각을 기준으로 합니다. 공지 API의 `createdDate`를 이 범위로 필터링해 최신 최대 3개를 표시합니다. 홈의 알림 버튼은 사용자 알림함을 엽니다. 알림 목록 API는 읽음 상태를 제공하지 않습니다.
- 전체 세션은 일정 탭으로 연결합니다. 전체 세션·출결 보고 카드는 Figma와 같은 70dp 높이로 표시합니다. 출석 점수와 내역은 My 탭에서 확인합니다.
- API 실패 시 입력을 보존하고 오류·재시도를 제공합니다. 제출 중에는 중복 확인·입력 수정·시트 닫기를 막습니다. 코드 불일치와 일반 요청 실패를 구분하며 성공 상태를 낙관적으로 만들지 않습니다.

## 세션 주소와 기기 거리 확인

- 홈은 세션의 장소명(`location`)과 도로명주소(`roadAddress`)를 표시합니다. 일정은 장소명 아래 도로명주소와 선택적 상세주소(`detailAddress`)를 표시합니다. 주소가 없으면 장소명을 표시합니다. 장소와 주소가 모두 없으면 홈의 기존 세션 라벨과 일정의 `-`를 표시합니다.
- 현재 Android 홈 카드는 장소명을 표시하며 도로명주소 표시는 후속 구현으로 남아 있습니다. [Android 이슈 #294 검증 기록](https://github.com/YAPP-admin/yapp-plus-android/issues/294)
- 홈 세션 카드에는 Figma 기준의 장소·세션·출석 상태를 표시합니다. 홈 카드에서 기기의 위치를 확인하는 시점은 [출석 코드 확인](#코드-출석-위치-조건)입니다. [Figma 홈](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=418-16033)
- 이번 주 세션 조회의 유효한 위도(`latitude`)와 경도(`longitude`)는 코드 출석의 거리 판정에 사용합니다. 서버는 TEAM과 주소 미등록 기존 세션에 이 필드를 null로 반환합니다.

## 코드 출석 위치 조건

- 홈 탭에 진입할 때 정밀 위치 권한이 없으면 Android가 대략적·정확한 위치 권한을 요청합니다. 이 권한 요청 시점에는 위치를 조회하지 않습니다.
- 코드 입력 가능 여부는 서버 출석 상태를 따릅니다. 출석 가능한 세션에서 4자리 코드를 확인할 때만 Android가 정확한 위치 권한을 요청하거나 현재 위치를 조회합니다.
- 유효한 세션 좌표, 정확한 위치 권한, 이번 시도에서 수신한 위치의 오차 50m 이하, 세션까지 반올림 전 직선거리 100m 이내를 모두 충족하면 `sessionId`와 `code`를 전송합니다. 위치 판정은 기기에서 하고 기기 위치와 계산값은 서버 전송과 영구 저장 없이 처리합니다.
- 홈 진입에 따른 위치 권한 자동 요청은 권한별 한 번만 표시합니다. 거부 뒤에도 코드 출석 확인을 누르면 기존 위치 권한 요청 흐름으로 다시 요청할 수 있습니다.
- 권한 부족, 위치 기능 꺼짐, 측정 실패·시간 초과, 정확도 부족, 범위 초과와 세션 좌표 누락을 안내합니다. 입력을 유지하며, 설정 복귀 후 사용자가 다시 확인해야 새 위치를 측정합니다. 위치 확인 중 화면에서 이탈한 시도의 응답은 코드 전송에 사용하지 않습니다.
- 근거는 사용자 요청, [iOS 위치 출석 명세](https://github.com/YAPP-admin/yapp-plus-frontend/blob/cc90b35ed70b9c1cca466f1d256fd20739017aef/specs/026-location-attendance/spec.md), [Android 이슈 #217](https://github.com/YAPP-admin/yapp-plus-android/issues/217)입니다.

## 출석 인증과 사전 보고 API 계약

- `POST /api/attendance-verifications`는 `sessionId`와 정수 `code`를 받습니다. 서버 응답의 `verified`와 `checkedInAt`으로 검증 성공을 판정하며 출석의 최종 확정과 점수 계산은 서버가 담당합니다.
- `POST /api/attendance-reports`는 `LATE`, `EARLY_LEAVE`, `ABSENT` 중 하나와 선택적 30자 이내 사유를 받습니다. 응답의 `sessionId`와 `submittedAt`으로 서버의 제출 결과를 확인합니다.
- 사전 보고 Data는 서버 오류 코드를 Domain 오류로 전달하며 `LATE`와 선택적 사유 계약을 검증합니다. 팀 사진은 SHA-256 체크섬으로 presign을 요청한 뒤 서명된 헤더를 붙여 별도 미인증 client로 업로드·제출합니다. 푸시 기기 등록·해제 Data 어댑터는 `ANDROID`를 사용합니다. Android 푸시는 로그인 상태와 기기 알림 권한을 확인해 등록합니다.
- Domain은 출석 코드 검증·사전 보고 Repository 계약과 보고 종류·코드 오류 표현을 정의합니다. Data의 DTO·YAPP API 어댑터와 App 연결은 구현됐으며 홈의 출석 코드 제출은 이 경로를 사용합니다. 홈의 보고 UI도 같은 경로를 사용합니다.

## 기기별 알림 설정

**적용 상태:** 설정의 알림 토글은 Android 앱 알림 설정을 열고 돌아온 뒤 시스템 권한·채널 상태를 표시합니다. App ViewModel은 기기별 선택을 해당 상태와 맞추며, 서버 기기 등록·해제는 App 조율자가 백그라운드에서 동기화합니다.

- 설정의 알림 토글은 현재 기기의 수신 여부를 뜻합니다. 화면에는 Figma의 **알림** 행을 유지하고, 기기별 동작을 설명하는 상시 문구를 추가하지 않습니다. 계정 전체의 알림 동의 값을 서버에 저장하지 않습니다. 알림함 조회와 다른 기기의 등록은 유지합니다.
- 설치별 선택은 세션과 분리한 백업 제외 DataStore에 저장합니다. 앱 재시작·로그아웃·재로그인에도 유지하며 재설치 후 복원은 보장하지 않습니다. 기존 초기 ON 동작을 유지하고 저장 내용이 손상되면 OFF로 복구합니다. 설정 화면에 진입하거나 시스템 앱 알림 설정에서 돌아올 때 Android 앱 권한·알림 채널 상태로 선택을 갱신합니다.
- 알림 토글을 누르면 현재 ON/OFF와 무관하게 Android 앱 알림 설정을 엽니다. 설정 화면은 시스템이 허용한 상태를 표시하며, 앱 권한 요청 대화상자나 별도 휴대폰 설정 행을 제공하지 않습니다.
- 홈 탭에 진입할 때 Android 13 이상에서 알림 권한이 없고 저장된 알림 선택이 ON이면 시스템 권한을 요청합니다. 선택이 OFF이면 자동 요청하지 않습니다. 알림과 위치 권한이 모두 필요하면 알림 요청을 먼저 표시합니다. 홈 진입에 따른 각 권한 자동 요청은 권한별 한 번으로 제한합니다.
- 선택을 갱신한 뒤 시작·로그인·토큰 갱신·화면 복귀의 자동 동기화가 기기를 등록·해제합니다. 등록은 FID·FCM 토큰으로 `PUT /api/users/me/notification-devices/{installationId}`, 해제는 현재 세션의 FID에 `DELETE`를 호출하며 등록이 없어도 DELETE는 성공할 수 있습니다. 서버 실패는 시스템 설정이나 화면 상태를 되돌리지 않고 설정 화면에 재시도 버튼을 표시하지 않습니다. 이후 앱 복귀·로그인·토큰 갱신 동기화에서 다시 시도합니다.
- OFF 상태는 시작·로그인·FCM 토큰 변경 시 재등록하지 않고 현재 기기 등록을 해제합니다. 메모리 캐시가 없는 앱 재시작에도 해제 요청을 보냅니다. 요청과 자동 동기화는 직렬화하며 도중에 세션이 바뀌어도 이전 세션 요청으로 설정을 저장하지 않습니다. 저장 선택이 OFF이면 로그인·홈 진입 때 Android 알림 권한을 자동 요청하지 않습니다.
- 로그아웃은 서버가 현재 세션의 등록을 해제하고 통합 탈퇴는 전체 등록을 해제합니다. 서버에서 이미 전송한 푸시는 OFF 처리 뒤에도 도착할 수 있습니다. 실제 수신은 Firebase 설정·Android 권한·서버 발송 상태에 의존합니다.
- 근거: 사용자 승인(2026-11-09), [이슈 #199](https://github.com/YAPP-admin/yapp-plus-android/issues/199), [백엔드 API 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/e2c2612a8652dc9c76f6ce7b6c26e97dbe8348c6/APIDOC.md). 계정 전체 알림 설정 조회·변경 API는 확인되지 않았습니다.

### Android 시스템 알림 설정

알림 화면은 OS의 앱 권한·알림 채널 상태를 기준으로 토글을 표시합니다. 토글은 Android 앱 알림 설정을 여는 진입점이며 서버 기기 등록·해제는 백그라운드 동기화로 처리합니다. 시스템 상태 조회나 서버 동기화 실패를 설정 변경 실패로 표시하거나 재시도 버튼으로 노출하지 않습니다.

## 일정·출석 정책

### 세션과 출석 대상

세션은 운영진이 주최하는 공식 일정이며 특정 기수에 포함됩니다. 동시에 진행되는 세션 중 한 세션에만 참석할 수 있습니다. 정기 세션은 매주 토요일입니다. 세션의 출석 대상은 해당 세션의 기수 활동 기록이 있고, 앱 역할이 활동회원이며, 해당 세션의 대상으로 선택된 회원입니다.

출석 화면은 출석 권한이 있는 회원에게 출석 대상 중 가장 가까운 세션을 표시합니다. 새 기수에 참여하는 OB와 프로젝트에 참여하는 운영진을 출석 대상으로 볼지는 미정입니다.

정규 세션의 코드 출석은 세션 시작 20분 전부터 세션 종료 시각까지 가능합니다. 2026년 11월 26일 확인한 기준입니다. [DEC-0089](decisions.md#dec-0089--정규-세션-출석-가능-시간)

### 출석 상태와 점수

| 상태 | 기준 | 기수 점수 |
| --- | --- | --- |
| 출석 | 세션 시작 20분 전부터 시작 10분 후까지 | 감점 없음 |
| 지각 | 시작 10분 후부터 시작 2시간 후까지 | 10점 감점 |
| 결석 | 지각 구간 이후의 출석 또는 무단 결석 | 20점 감점 |
| 미출석 | 출석 기록 없이 세션이 종료됨 | 결석과 같이 20점 감점 |
| 공결 | 경조사 등 특수 사유를 이사회가 심의해 인정, 기수별 최대 1회 | 감점 없음 |
| 조퇴 | 기준과 감점이 정해지지 않음 | 미정 |

출석 점수는 기수마다 100점에서 시작하고 기수가 끝나면 초기화합니다. 회원은 언제든 본인 점수를 확인할 수 있습니다. 70점 이상은 활동 기간 이수 기준이며, 40점 이하는 제적 심의 대상입니다. 이사회는 가점을 주거나 감점을 면제할 수 있으며, 기존 “지각 면제권”도 이 판단에 포함됩니다. 점수 합산은 100 − 10 × 지각 횟수 − 20 × (결석 + 미출석 횟수) + 이사회 가점·감점 면제 점수이며 공결은 감점하지 않습니다.

OB에게는 결석 허용 횟수를 전체 세션 수의 1/3로 계산해 소수점 이하를 버려 표시합니다. 이를 초과해 결석하면 해당 기수의 활동 자격을 즉시 잃고, 이후 이사회가 제적 여부를 심의합니다.

Notion 표에는 출석·지각·결석의 시간 구간이 제시되어 있지만 같은 문서가 10분 경계의 초 단위 판정과 지각 종료가 시작 후 2시간인지 2시간 10분인지 확인이 필요하다고 표시합니다. 이 경계는 확정 전까지 코드 판정에 적용하지 않습니다.

### 출석·일정 화면

- 홈 출석 버튼의 활성화 여부는 서버의 출석 UI 상태를 따릅니다. 시간 전에는 세션 날짜·시작 시각으로 안내하고, 출석 가능 상태에서 활성화합니다.
- 홈 코드 검증 성공 화면은 수정된 Figma의 “출석을 완료했어요!”를 표시합니다. 서버 검증 응답에 시간 구간별 판정 상태가 없어 기존 구간별 평가 문구는 아직 적용하지 않습니다. 시간 구간의 정책은 앞의 미확정 경계에 따릅니다.
- 홈의 이번 달 세션은 활성 기수에서 설정된 월의 세션만 시작일·시작 시간·종료일·종료 시간 오름차순으로 표시합니다. 종료된 세션은 오늘 날짜의 세션이라도 과거로 보고 흐리게 처리하고, 아직 끝나지 않은 당일 세션과 미래 세션을 구분합니다. 홈 진입 시 당일의 가장 가까운 예정 세션을 가운데에 표시합니다.
- 세션 일정은 활성 기수의 전체 세션을 표시합니다. 종료된 세션은 흐리게 하고 출석 정보를 표시하며, 오늘 세션은 강조하고, 미래 세션은 “예정” 칩으로 표시합니다. 종료 시간이 지났고 기록이 없으면 미출석(결석)으로 취급합니다.
- 오늘의 세션 화면은 활성 기수에서 오늘 진행하는 세션을 보여 주고 세션명·시작일·장소·시작 시간·종료 시간을 표시합니다. 하루 여러 세션 지원과 대체 정보 배치는 출처에서 개선안으로 표시되어 확정 범위에 넣지 않습니다.
- 월간 전체 일정에는 선택한 연·월의 일정을 표시합니다. 세션에는 이름·장소·시간·출석 상태를 표시합니다. 과거 일정은 흐리게, 오늘 일정은 강조합니다. 태스크와 기타 일정의 표현은 미정입니다.
- 최근 출석 현황과 출석 내역은 세션명·출석 처리 시각·상태를 표시합니다. 기록이 있는 세션과 기록 없이 끝난 세션을 포함하며, 기록이 있는 미래 세션도 나타날 수 있습니다. 종료 세션의 기록 없음은 결석(미출석)으로 표시합니다.
- 출석 내역에는 상태별 횟수와 총점을 표시합니다. 세션 현황에는 전체·남은 세션 수를 제공합니다. Notion의 진행률 식은 남은 세션 비율을 계산하는 것으로 보인다고 출처에서 확인을 요청했으므로 진행률 계산은 미정입니다.

## 기타 화면 정책

- My 화면은 이름과 서버가 선택한 소속의 회원 구분·기수·직군을 표시하고 출석 내역·이전 활동 내역·이용 문의·회원탈퇴 메뉴를 제공합니다. 이용 문의는 [YAPP 카카오톡 채널](https://pf.kakao.com/_aGxofd)을 엽니다. 설정의 회원 탈퇴는 통합 탈퇴 API를 호출하고 확인 문구는 아래 Figma 기준을 따릅니다. 최신 My 메뉴 구성은 아래 Figma 기준을 따릅니다.
- 공지 사용자 API는 `GET /api/posts`의 유형·커서 목록, `GET /api/posts/{id}`의 상세·과제·이미지, `PUT /api/posts/{id}/read`의 읽음을 제공합니다. Data에서 서버 시각·유형·읽음·첨부를 Domain으로 변환하고 게시판과 홈 주간 공지에 연결합니다.
- 게시판은 Figma의 전체·세션·과제·기타 필터와 Markdown 본문, 과제 마감·제출 대상, 첨부 이미지와 읽음 확인 버튼을 제공합니다. 이미지는 서명 URL이며 디스크·메모리 캐시를 사용하지 않습니다. 조회·페이지·읽음 결과는 화면 상태와 콜백으로 받고 ViewModel이 API 요청·실패·재시도를 관리합니다. 기수별 필터는 출처에서 개선안으로 표시해 확정 정책에 포함하지 않습니다.
- 설정의 알림은 현재 기기의 푸시 수신 선택입니다. Figma의 알림 행을 유지하며 서버의 기기 등록·해제 성공 뒤 선택을 저장·반영합니다. 다른 기기의 등록과 알림함 조회는 유지합니다. 이용약관은 각 약관의 Notion 페이지로 연결하고 Figma에 없는 앱 버전은 표시하지 않습니다.
- 이전 활동 이력은 기수·직군 조합이며 시작일과 종료일은 비어 있을 수 있습니다. 회원 용어와 공식 직군 범위는 [회원·역할 정책](membership-policy.md)을 따릅니다.

## Firebase 푸시

- Android 설정 파일은 Debug에서 `yappplus-dev`의 `com.yapp.plus.debug` 앱, Release에서 `yappplus-prod`의 `com.yapp.plus` 앱을 사용합니다. Google OAuth Android 클라이언트도 각 패키지명과 서명 SHA-1에 맞게 등록합니다. App은 프로젝트, 로그인 세션, 저장된 수신 선택과 시스템 알림 권한을 확인해 기기를 등록합니다. 서버는 로그아웃 시 해당 세션의 기기 등록을 삭제합니다.
- 푸시의 `source=POST`와 양의 `postId`가 있을 때 공지 상세를 엽니다. 로그인하지 않은 경우 세션이 생긴 뒤 이동합니다. 공지 상세의 조회 실패는 게시판의 기존 오류 처리를 따릅니다. [서버 알림 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/e2c2612a8652dc9c76f6ce7b6c26e97dbe8348c6/APIDOC.md#운영진-알림과-기기-등록)

- 세션 자동 알림 푸시도 같은 일정 이동 계약을 사용합니다. 로그인 전 수신한 이동 요청은 인증된 화면이 열린 뒤 처리합니다.

## My 본인 프로필 조회

- `GET /api/users/me`는 Bearer access token으로 본인을 조회하며 요청 파라미터와 본문이 없습니다. 성공 시 `userId`(Long), `name`(String)을 반환합니다. 소속이 있으면 `membershipStatus`, `generationId`(Long), `generationNumber`(Int)가 함께 있고 `position`은 비어 있을 수 있습니다. 소속이 없으면 이 네 값은 모두 `null`입니다. 표시할 소속은 서버가 선택하며 앱은 `generationNumber`를 기수 번호로 사용합니다. [백엔드 프로필 조회 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/c26950683839f46d6778c2ba0e651a77cec27146/APIDOC.md#L1235-L1258)
- My 진입·재진입 시 조회하고 성공 응답의 이름을 표시합니다. 조회 중이거나 실패하면 인증·가입 시 세션에 저장한 이름을 표시합니다. 정상 무소속은 조회 성공이며, 비어 있거나 앱이 모르는 필드의 표시는 회원·역할 정책을 따릅니다. [회원 구분·직군 표기](membership-policy.md#my-프로필의-회원-구분과-직군)
- `401`은 기존 인증 client의 세션 갱신·한 번 재시도를 따릅니다. `409 ACTIVE_GENERATION_CONFLICT`와 `503 USER_PROFILE_UNAVAILABLE`는 조회 실패로 전달하며 My는 진입 시 프로필을 출석 점수와 독립적으로 요청합니다.
- `UserProfileReadRepository`에 인증 HTTP 어댑터를 조립하고 My 진입·재진입에 연결했습니다. [이슈 #185](https://github.com/YAPP-admin/yapp-plus-android/issues/185)

## 계정·기수 통합 탈퇴

2026-10-27 확인한 dev 서버의 `DELETE /api/users/me`는 앱 계정과 동아리 회원 자격을 함께 종료하는 통합 탈퇴 API입니다. Bearer access token이 필요하고 요청 본문 없이 성공 시 `204 No Content`를 반환합니다. 모든 기수 Membership을 `WITHDRAWN`으로 변경하고 모든 세션을 폐기하며, 개인정보를 비식별화하고 운영·출결 이력의 연결 ID를 보존합니다. Native 앱은 서버 성공 뒤에만 로컬 token 쌍을 삭제하고 로그인 화면으로 이동합니다. 실패하면 세션을 유지해 다시 시도할 수 있게 합니다. 설정 확인 팝업 문구는 사용자의 2026-10-29 명시적 지시에 따라 Figma 원문을 사용합니다. 서버의 비식별화·이력 보존 동작은 유지합니다. 재가입 시 새 User에 [동일한 가입·승인 기준](#회원가입과-승인)을 적용합니다. [서버 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/c7685e86a9c6d2514ab158444a1f4812de57d919/APIDOC.md#12-계정동아리-통합-탈퇴)을 따릅니다.

사용자가 요청한 dev 계정의 직접 API 탈퇴에서 `204`, 기존 token의 인증 요청 거절 `401`, 로컬 token 삭제와 프로세스 재시작 후 로그인 화면을 확인했습니다. 이슈 #149는 Domain 계약, Data API, 설정 안내, App 인증 흐름 순서로 나눴으며 이 작업에서 설정 콜백까지 연결했습니다. App 단위 테스트 8건과 API 35 에뮬레이터 UI 테스트 6건으로 요청 상태·실패 재시도·취소·로그인 복귀·Main back stack 제거를 확인했습니다. 이 검증은 Fake Repository와 모의 콜백을 사용하며, 실제 Settings 화면에서의 서버 탈퇴 E2E는 확인하지 않았습니다.

## 사용자 조회·제출 계약의 분리 반영

[백엔드 f1d29f4](https://github.com/YAPP-admin/yapp-plus-backend/tree/f1d29f44bfbf10793baabce7c0e2f2efdf3a307c)에서 확인한 출석 점수·커서 이력, 공지 목록·상세·과제·읽음, 인증 응답 이름, 팀 사진과 푸시 기기의 Domain 모델·Repository 계약을 정의했습니다. My 출석 점수·이력 조회 Data 어댑터와 인증 응답 이름 저장을 반영했습니다. 점수는 서버 값을 사용하고 이력의 미확정·TEAM 검토 상태를 보존합니다. 문서화된 자격·현재 기수 없음만 값 없는 점수로 처리하며 다른 오류는 실패로 전달합니다. 공지·팀 사진·푸시 기기의 Data 어댑터와 공통·설정·보고·게시판 상세·My 요약 UI까지 PR #162~#171로 병합했습니다. 가입 Route 정리, App Repository 조립, My 화면과 조회·이동, 게시판과 홈의 API 연결을 PR #172~#178로 나누어 반영했습니다. 팀원 정보·본인 membershipId·Firebase 설정 및 미확인 회원 필드를 임의의 값으로 채우지 않습니다.

팀 사진 출석 결과 UI는 사진 제출 완료와 출석 확정을 구분합니다. 팀 홈 카드는 세션 시간 범위, 출석 가능 여부, 조회 진행·실패 안내, 검토 요약과 결과 진입을 표현합니다. 업로더 이름이나 열람할 사진이 없으면 제공된 검토 정보만 표시합니다. 검토 중·승인·반려·미선택·실패 표시는 debug Preview에서 확인할 수 있습니다. 실제 홈 연결에는 아래 사용자 조회 계약을 사용합니다.

## 사용자 팀 출석 조회

- `GET /api/sessions/{sessionId}/team-members`는 현재 팀의 선택 가능한 PLAYER와 본인 표시 `isMe`를 제공합니다. 선택·제출에는 기수 소속 ID인 `membershipId`를 사용합니다. 직군은 없을 수 있습니다.
- `GET /api/sessions/{sessionId}/team-attendance-photos`는 권한이 있는 최신 제출의 사진 상태, 업로더 이름, 업로드·제출 시각, 선택 인원 수를 제공합니다. 사진이 없으면 `photo: null`입니다. 이미지 링크는 만료되거나 없을 수 있습니다.
- 홈은 제출 안내의 한국 시간 세션 구간 안에서 팀원 선택과 제출을 허용하며, 서버 검토 상태와 업로드 정보를 표시합니다. 결석은 개인 출석 이력으로 확인합니다. 사용자 응답은 제출 당시 선택 인원 수를 제공하며, 현재 팀 명단으로 제출 당시 참석자를 추정하지 않습니다.
- 사용자 응답의 `photo.rejectionReason`은 반려된 사진에 운영진이 사유를 저장했을 때 문자열로 제공됩니다. 앱은 해당 사유를 반려 시트에 표시하고, 값이 없거나 공백이면 사유 영역을 숨깁니다. ## 커뮤니티 뒤풀이와 정산

- 커뮤니티와 홈은 사용자 Bearer 인증으로 초대받은 뒤풀이를 조회합니다. 참석 여부는 전체·진행 중·투표 마감 필터를 제공하고, 정해진 마감 전에는 참석·불참을 제출하거나 바꿀 수 있습니다. 현재 응답이 있는 회원만 참석자 명단을 볼 수 있습니다.
- 참석자는 현재 참석 후보에게 정산을 요청할 수 있습니다. 정산자와 유효 대상자는 각자 관여한 정산만 조회합니다. 정산자만 수금 현황·명단과 수정 원본을 볼 수 있고, 납부 표시는 유효 대상자 본인이 변경합니다. 이체는 사용자가 계좌로 직접 합니다.
- 정산 수정은 원본 revision을 전달합니다. 납부 완료자가 있으면 계좌·금액·대상 변경을 막고 증빙 사진만 수정합니다. 첨부는 JPEG·PNG 최대 5장, 장당 10MB로 제한하며 SHA-256과 서명 URL을 사용합니다. 서명 URL과 계좌는 영구 저장하거나 로그에 남기지 않습니다.
- MY에서 보낼 돈·받을 돈을 조회할 수 있고 정산 생성·미납 알림은 해당 정산을 엽니다. 미납 리마인드 발송은 서버가 맡습니다.
- 정산 등록을 마치면 뒤풀이 상세에서 서버가 반환한 정산 요청 인원으로 완료 토스트를 표시합니다. 보낼 돈은 뒤풀이별 미송금 정산의 인당 금액을 합산하며, 송금 화면에서는 해당 뒤풀이의 정산별 완료 표시와 되돌리기를 지원합니다. 받을 돈과 정산 현황의 진행 상태는 정산자가 조회한 수금 인원과 대상 인원을 사용합니다.
- Figma의 차수별 투표, 비참석 회원 추가, 수동 미납 알림은 사용자 계약에 없습니다. Android는 단일 참석 응답과 현재 참석 후보를 사용합니다. 정산 등록 가능 시점과 원 단위 금액은 서버 계약을 따릅니다.
- 납부자용 응답에 송금 완료 날짜와 정산 알림 확인 상태가 없으므로, 송금 완료 날짜와 정산 목록의 미확인 표시를 보류합니다.
- 정산 작성·수정 화면의 소수점 보기는 총 금액을 정산 인원으로 나눈 결과를 소수 둘째 자리까지 표시합니다. 실제 정산 요청에는 사용자가 확인한 원 단위 인당 금액을 전송합니다.
