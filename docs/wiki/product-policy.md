# 제품 정책

앱 동작은 확인된 제품 요구사항과 API 계약을 기준으로 정합니다. 화면이 표시하는 진행·예상 상태와 서버가 확정한 출석 결과를 구분합니다. YAPP의 2026 출석 규칙을 확인했으며, 출석 코드 검증·사전 출결 보고는 확인된 서버 계약으로 호출합니다. 실제 판정·점수 계산은 서버가 담당합니다. 홈의 이번 주 세션 요약과 일정 화면은 세션 조회 API를 표시합니다. 공지·My 회원 정보·출석 기록·점수 API는 아직 연결하지 않았으며, 해당 화면은 준비 중 상태를 표시합니다.

**현재 구현 상태:** 개발 앱은 YAPP 서버의 Google 인증·가입과 세션·출석 API를 사용합니다. 가입 완료 뒤 멤버십 연결·운영진 승인은 별도이며, 팀 사진 출석·검수, 공식 회원·출석 이력 조회, 공지 및 알림 API는 연결되지 않았습니다. 출결 보고 계약은 Data·Domain에 있으나 홈 진입은 연결 전까지 숨깁니다. My·공지와 알림은 준비 중 정책을 따릅니다. 이 절은 목표 요구를 기록하며 현재 기능의 완료를 뜻하지 않습니다.

## 개발과 비공개 테스트 배포

- `release/v1.0.1`은 기존 비공개 테스트 버전을 보존합니다. 실제 서비스 개발은 `develop` 기반 작업 브랜치에서 진행합니다.
- 같은 Google Play 앱과 `applicationId` `com.yapp.plus`를 사용하고 비공개 테스트 트랙으로 배포합니다.
- 임시 테스트 브랜치를 실제 개발 브랜치에 통째로 병합하지 않습니다. 필요한 수정만 검토해 반영하고, 실제 서비스의 배포 후보는 최신 `develop`에서 새 릴리즈 브랜치로 준비합니다.
- 임시 테스트 전용 백엔드 구현·SQL·문서는 개발 버전에서 제거합니다. 기존 배포의 외부 서비스와 데이터는 유지합니다.

## 로그인·가입 구현 범위

개발 앱은 Google Credential Manager의 서버 Client ID에 Web Client ID를 사용합니다. 매 요청마다 원본 nonce를 만들고 그 SHA-256 소문자 hex를 Google 요청에 넣은 뒤, 받은 ID Token과 원본 nonce를 `POST /api/auth/oidc/google/native-authentications`에 보냅니다. Google Client Secret은 클라이언트에 포함하지 않습니다. ID Token·원본 nonce는 메모리에서만 전달하고 저장하거나 로그로 남기지 않습니다.

`SIGNED_IN` 응답은 access/refresh token 쌍을 암호화 저장하고 메인으로 이동합니다. `SIGNUP_REQUIRED` 응답의 일회용 registration token은 App 메모리에만 두고 가입 화면으로 전달합니다. 가입은 기존 `POST /api/users`에 registration token·이름·E.164 전화번호를 보내며, 성공 응답의 세션을 저장합니다. 앱 시작 때 저장 세션을 복원해 메인 또는 로그인 화면을 선택합니다. 로그인 실패는 재시도할 수 있고, 가입 실패는 입력을 유지하며 응답 코드에 맞춰 재시도 또는 다시 로그인할 수 있습니다.

가입 이름·휴대폰 입력은 `:feature:signup`에서 관리하고 복원합니다. 한국 휴대폰 번호는 E.164 형식으로 변환해 보냅니다. registration token은 Navigation 인자나 `SavedStateHandle`에 저장하지 않으며, 프로세스 종료 후 유실되면 Google 로그인을 다시 진행합니다. 가입 성공은 사용자 생성 완료를 의미하고 멤버십 승인 처리는 별도입니다. 과거 완료 단계가 저장돼 있어도 휴대폰 입력으로 복원합니다.

가입 입력 오류는 `fieldErrors`의 `field`와 `code`로 구분하고 입력창에 표시합니다. 이름만 오류이면 이름 입력으로 돌아가며 전화번호를 유지합니다. 이름을 수정하면 전화번호 입력을 다시 받지 않고 기존 번호와 가입 토큰으로 재제출합니다. 두 입력 모두 오류이면 이름을 먼저 수정한 뒤 보관된 전화번호를 표시하고 번호도 수정합니다. 전화번호 중복은 전화번호 입력 오류로 처리하며, 필드 오류가 없는 인증·서버 오류는 기존 팝업으로 처리합니다. 이름 검증은 필수·형식·최대 100자 조건이며 실명·명단 일치 검증을 뜻하지 않습니다. [API 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/dev/APIDOC.md#8-user-가입-완료)을 따릅니다.

## 현재 서버 연결

확인 근거는 서버 OpenAPI와 [백엔드 dev 인증 Controller](https://github.com/YAPP-admin/yapp-plus-backend/blob/dev/api/src/main/kotlin/backend/yappplus/auth/AuthController.kt)입니다.

| 기능 | 계약과 적용 상태 |
| --- | --- |
| 이번 주 세션 | `GET /api/sessions/current-week`; YAPP RemoteDataSource·Repository·홈 ViewModel·App 연결 |
| 현재 기수 일정 | `GET /api/generations/current/sessions`; YAPP RemoteDataSource·Repository·일정 Feature·App 연결 |
| 출석 인증 | `POST /api/attendance-verifications`; 서버 확인 후에만 완료 표시 |
| 사전 보고 | `POST /api/attendance-reports`; Data·Domain·App 연결 유지, 홈 보고 UI 연결은 후속 |
| 세션 갱신 | `POST /api/auth/session-renewals`; 암호화 저장·복원과 401 뒤 한 번 재시도 구현 |
| Google 로그인 | `POST /api/auth/oidc/google/native-authentications`; `SIGNED_IN` 세션 저장·메인 이동, `SIGNUP_REQUIRED` 가입 토큰을 Signup으로 전달 |
| 회원가입 | `POST /api/users`; registration token·이름·E.164 전화번호 제출, 성공 응답 세션 저장 |
| 로그아웃 | `DELETE /api/auth/sessions/current`; 현재 refresh token을 전달하고 성공 응답 뒤 로컬 token 쌍을 삭제해 로그인 화면으로 이동. 실패하면 세션을 유지하고 다시 시도 |
| 공지·My | 사용자용 API 연결은 후속; 현재 준비 중 상태 표시 |
| 통합 탈퇴 | `DELETE /api/users/me`; Bearer access token으로 요청하고 성공 응답 뒤 로컬 token 쌍을 삭제해 로그인 화면으로 이동. 실패하면 세션을 유지하고 다시 시도. 설정 안내·확인·진행·오류와 App 연결 구현 |

저장된 YAPP 토큰 쌍은 앱 시작과 첫 인증 API 요청 전에 복원합니다. 초기 Google 세션 발급은 YAPP API 계약에 연결했습니다. 로컬 access-token 주입이나 가짜 인증 세션은 만들지 않습니다.

## 수정된 홈 화면과 연결 흐름

YAPP 서버의 출석 인증·보고 계약을 따릅니다. 홈의 보고 UI는 후속 연결 전까지 숨깁니다.

- 기준은 사용자가 변경을 확정한 [Figma 홈 섹션](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=222-40284)과 [이슈 #82](https://github.com/YAPP-admin/yapp-plus-android/issues/82)입니다. 홈 메인·알림·출석 코드 입력/완료·출결 보고 화면까지 적용합니다.
- 홈은 이번 주 세션의 장소·제목, 일요일부터 토요일까지의 달력, 출석 상태와 빠른 메뉴, 이번 주 공지를 표시합니다. 오늘은 원형으로, 세션 날짜는 브랜드 색상으로 구분합니다. 서버의 `AVAILABLE` 상태에서만 출석 버튼을 활성화합니다.
- 4자리 숫자 입력은 붙여넣기와 숫자 키보드를 지원합니다. 입력 형식 검증 뒤 `POST /api/attendance-verifications`에 `sessionId`와 정수 `code`를 전달합니다. `verified=true`와 유효한 `checkedInAt`을 받은 뒤에만 완료 화면과 해당 세션의 출석 완료 상태를 표시합니다. 조회 API에는 완료 상태가 없어 이 상태는 현재 ViewModel 생명주기 안에서만 유지합니다.
- 보고는 지각·조퇴·결석 선택 후 30자 이내의 선택적 사유를 입력합니다. 서버의 `POST /api/attendance-reports`에는 `LATE`, `EARLY_LEAVE`, `ABSENT` 중 하나와 사유를 보냅니다. 응답의 `sessionId`·`submittedAt`을 확인한 뒤 완료 안내를 표시합니다. 서버의 허용 시간과 점수를 클라이언트에서 재판정하지 않습니다.
- 2026-10-30 확인한 사용자 Controller는 `LATE`를 허용합니다. 지각의 추가 시간 선택 없이 서버 계약을 사용하며 사유 길이는 Kotlin `String.length` 기준 최대 30입니다. 사유 생략과 빈 문자열을 허용합니다.
- 홈의 이번 주 공지는 한국 시간의 일요일 00:00부터 다음 일요일 전까지의 게시 시각을 기준으로 합니다. 공지 API 연결 전에는 준비 중 상태를 표시합니다. 알림 조회·읽음 처리와 푸시 연동 전까지 홈 알림 진입을 숨깁니다. 알림 컴포넌트와 debug Preview는 보존합니다.
- 전체 세션은 일정 탭으로 연결합니다. 전체 세션·출결 보고 빠른 메뉴 카드는 Figma의 동일한 70dp 높이로 표시하며 출결 보고의 제출 연결은 후속입니다. 미연동된 출석 점수 메뉴는 숨깁니다. My의 회원 정보·점수·기록 API 연결은 후속입니다.
- API 실패 시 입력을 보존하고 오류·재시도를 제공합니다. 제출 중에는 중복 확인·입력 수정·시트 닫기를 막습니다. 코드 불일치와 일반 요청 실패를 구분하며 성공 상태를 낙관적으로 만들지 않습니다.

## 출석 인증과 사전 보고 API 계약

- `POST /api/attendance-verifications`는 `sessionId`와 정수 `code`를 받습니다. 서버 응답의 `verified`와 `checkedInAt`으로 검증 성공을 판정하며 출석의 최종 확정과 점수 계산은 서버가 담당합니다.
- `POST /api/attendance-reports`는 `LATE`, `EARLY_LEAVE`, `ABSENT` 중 하나와 사유를 받습니다. 응답의 `sessionId`와 `submittedAt`으로 서버의 제출 결과를 확인합니다.
- Domain은 출석 코드 검증·사전 보고 Repository 계약과 보고 종류·코드 오류 표현을 정의합니다. Data의 DTO·YAPP API 어댑터와 App 연결은 구현됐으며 홈의 출석 코드 제출은 이 경로를 사용합니다. 보고 UI 연결은 후속입니다.

## 일정·출석 정책

### 세션과 출석 대상

세션은 운영진이 주최하는 공식 일정이며 특정 기수에 포함됩니다. 동시에 진행되는 세션 중 한 세션에만 참석할 수 있습니다. 정기 세션은 매주 토요일입니다. 세션의 출석 대상은 해당 세션의 기수 활동 기록이 있고, 앱 역할이 활동회원이며, 해당 세션의 대상으로 선택된 회원입니다.

출석 화면은 출석 권한이 있는 회원에게 출석 대상 중 가장 가까운 세션을 표시합니다. 출석은 세션 시작 20분 전부터 종료 시간까지 가능합니다. 새 기수에 참여하는 OB와 프로젝트에 참여하는 운영진을 출석 대상으로 볼지는 미정입니다.

### 출석 상태와 점수

| 상태 | 기준 | 기수 점수 |
| --- | --- | --- |
| 출석 | 세션 시작 20분 전부터 시작 10분 후까지 | 감점 없음 |
| 지각 | 시작 10분 후부터 시작 2시간 후까지 | 10점 감점 |
| 결석 | 지각 구간 이후의 출석 또는 무단 결석 | 20점 감점 |
| 미출석 | 출석 기록 없이 세션이 종료됨 | 결석과 같이 20점 감점 |
| 공결 | 경조사 등 특수 사유를 이사회가 심의해 인정, 기수별 최대 1회 | 감점 없음 |
| 조퇴 | 기준과 감점이 정해지지 않음 | 미정 |

출석 점수는 기수마다 100점에서 시작하고 기수가 끝나면 초기화합니다. 회원은 언제든 본인 점수를 확인할 수 있습니다. 70점 이상은 활동 기간 이수 기준이며, 40점 이하는 제적 심의 대상입니다. 이사회는 가점을 주거나 감점을 면제할 수 있으며, 기존 “지각 면제권”도 이 판단에 포함됩니다. 점수 합산은 100 − 10 × 지각 횟수 − 20 × (결석 + 미출석 횟수) + 이사회 가점·감점 면제 점수이며 공결은 감점하지 않습니다.

OB에게는 결석 허용 횟수를 전체 세션 수의 1/3로 계산해 소수점 이하를 버려 표시합니다. 이를 초과해 결석하면 해당 기수의 활동 자격을 즉시 잃고, 이후 이사회가 제적 여부를 심의합니다.

Notion 표에는 출석·지각·결석의 시간 구간이 제시되어 있지만 같은 문서가 10분 경계의 초 단위 판정과 지각 종료가 시작 후 2시간인지 2시간 10분인지 확인이 필요하다고 표시합니다. 이 경계는 확정 전까지 코드 판정에 적용하지 않습니다.

### 출석·일정 화면

- 홈 출석 버튼의 활성화 여부는 서버의 출석 UI 상태를 따릅니다. 시간 전에는 세션 날짜·시작 시각으로 안내하고, 출석 가능 상태에서 활성화합니다.
- 홈 코드 검증 성공 화면은 수정된 Figma의 “출석을 완료했어요!”를 표시합니다. 서버 검증 응답에 시간 구간별 판정 상태가 없어 기존 구간별 평가 문구는 아직 적용하지 않습니다. 시간 구간의 정책은 앞의 미확정 경계에 따릅니다.
- 홈의 이번 달 세션은 활성 기수에서 설정된 월의 세션만 시작일·시작 시간·종료일·종료 시간 오름차순으로 표시합니다. 종료된 세션은 오늘 날짜의 세션이라도 과거로 보고 흐리게 처리하고, 아직 끝나지 않은 당일 세션과 미래 세션을 구분합니다. 홈 진입 시 당일의 가장 가까운 예정 세션을 가운데에 표시합니다.
- 세션 일정은 활성 기수의 전체 세션을 표시합니다. 종료된 세션은 흐리게 하고 출석 정보를 표시하며, 오늘 세션은 강조하고, 미래 세션은 “예정” 칩으로 표시합니다. 종료 시간이 지났고 기록이 없으면 미출석(결석)으로 취급합니다.
- 오늘의 세션 화면은 활성 기수에서 오늘 진행하는 세션을 보여 주고 세션명·시작일·장소·시작 시간·종료 시간을 표시합니다. 하루 여러 세션 지원과 대체 정보 배치는 출처에서 개선안으로 표시되어 확정 범위에 넣지 않습니다.
- 월간 전체 일정에는 선택한 연·월의 일정을 표시합니다. 세션에는 이름·장소·시간·출석 상태를 표시합니다. 과거 일정은 흐리게, 오늘 일정은 강조합니다. 태스크와 기타 일정의 표현은 미정입니다.
- 최근 출석 현황과 출석 내역은 세션명·출석 처리 시각·상태를 표시합니다. 기록이 있는 세션과 기록 없이 끝난 세션을 포함하며, 기록이 있는 미래 세션도 나타날 수 있습니다. 종료 세션의 기록 없음은 결석(미출석)으로 표시합니다.
- 출석 내역에는 상태별 횟수와 총점을 표시합니다. 세션 현황에는 전체·남은 세션 수를 제공합니다. Notion의 진행률 식은 남은 세션 비율을 계산하는 것으로 보인다고 출처에서 확인을 요청했으므로 진행률 계산은 미정입니다.

## 기타 화면 정책

- My 화면은 이름, 앱 권한 역할, 최근 활동 이력(기수·직군)을 표시하고 출석 내역·이전 활동 내역·이용 문의·회원탈퇴 메뉴를 제공합니다. 이용 문의는 카카오톡 오픈 채팅방으로 이동합니다. 설정의 회원 탈퇴는 통합 탈퇴 API를 호출하고 확인 문구는 아래 Figma 기준을 따릅니다. 개발 버전의 My 정보는 준비 중 상태이며, 프로필·출석 조회 API는 후속입니다.
- 공지사항은 운영 공지와 세션 공지로 나누고 유형별 필터와 날짜 내림차순 정렬을 제공합니다. 기수별 필터는 출처에서 개선안으로 표시해 확정 정책에 포함하지 않습니다.
- 설정의 알림은 앱 푸시 전체 설정이며 해제하면 푸시를 보내지 않습니다. 사용자 지시에 따라 Figma의 알림 토글을 표시하되 현재는 화면 상태만 변경·복원합니다. 푸시 전달과 서버 설정 저장은 미연결입니다. 이용약관은 각 약관의 Notion 페이지로 연결하고 Figma에 없는 앱 버전은 표시하지 않습니다.
- 이전 활동 이력은 기수·직군 조합이며 시작일과 종료일은 비어 있을 수 있습니다. 회원 용어와 공식 직군 범위는 [회원·역할 정책](membership-policy.md)을 따릅니다.

## 계정·기수 통합 탈퇴

2026-10-27 확인한 dev 서버의 `DELETE /api/users/me`는 앱 계정과 동아리 회원 자격을 함께 종료하는 통합 탈퇴 API입니다. Bearer access token이 필요하고 요청 본문 없이 성공 시 `204 No Content`를 반환합니다. 모든 기수 Membership을 `WITHDRAWN`으로 변경하고 모든 세션을 폐기하며, 개인정보를 비식별화하고 운영·출결 이력의 연결 ID를 보존합니다. Native 앱은 서버 성공 뒤에만 로컬 token 쌍을 삭제하고 로그인 화면으로 이동합니다. 실패하면 세션을 유지해 다시 시도할 수 있게 합니다. 설정 확인 문구는 사용자의 Figma 원문 유지 지시를 따르며 서버의 비식별화·이력 보존 계약은 바꾸지 않습니다. 재가입은 새 User와 승인 절차로 시작합니다. [서버 계약](https://github.com/YAPP-admin/yapp-plus-backend/blob/dev/APIDOC.md#11-계정동아리-통합-탈퇴)을 따릅니다.

사용자가 요청한 dev 계정의 직접 API 탈퇴에서 `204`, 기존 token의 인증 요청 거절 `401`, 로컬 token 삭제와 프로세스 재시작 후 로그인 화면을 확인했습니다. 이슈 #149는 Domain 계약, Data API, 설정 안내, App 인증 흐름 순서로 나눴으며 이 작업에서 설정 콜백까지 연결했습니다. App 단위 테스트 8건과 API 35 에뮬레이터 UI 테스트 6건으로 요청 상태·실패 재시도·취소·로그인 복귀·Main back stack 제거를 확인했습니다. 이 검증은 Fake Repository와 모의 콜백을 사용하며, 실제 Settings 화면에서의 서버 탈퇴 E2E는 확인하지 않았습니다.
