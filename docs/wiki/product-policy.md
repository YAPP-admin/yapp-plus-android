# 제품 정책

앱 동작은 확인된 제품 요구사항과 API 계약을 기준으로 정합니다. 화면이 표시하는 진행·예상 상태와 서버가 확정한 출석 결과를 구분합니다. YAPP의 2026 출석 규칙을 확인했으며, 출석 코드 검증·사전 출결 보고는 확인된 서버 계약으로 호출합니다. 실제 판정·점수 계산은 서버가 담당하고 출석 기록 조회는 후속입니다. 홈의 이번 주 세션 요약과 일정 화면은 세션 조회 API를 표시하며, 출석 기록 API가 연동되기 전까지 홈에는 최근 출석 이력을 표시하지 않습니다. 게시판·My 화면은 데모 상태이고, 실제 회원 정보와 출석 기록은 아직 표시하지 않습니다.

## Supabase 기반 비공개 테스트 MVP

- 사용자 승인과 [이슈 #90](https://github.com/YAPP-admin/yapp-plus-android/issues/90)에 따라 Google 로그인, 출석하기, 세션 조회, 공지 조회를 비공개 테스트 MVP 범위로 정했습니다. Google Credential Manager의 ID 토큰과 원본 nonce를 Supabase Auth에 교환하고, 발급된 인증 세션의 앱 재시작 후 복원과 로그아웃을 제공합니다. Google ID 토큰 발급 자체는 로그인 완료를 의미하지 않습니다.
- 세션·공지 테스트 데이터는 Supabase migration/seed로 제공하고 홈·일정·게시판에서 Repository를 통해 조회합니다. 실제 회원 가입·승인, YAPP 회원 정보·점수·원본 서버의 초기 로그인 계약은 이 MVP 범위에서 임의로 만들지 않습니다.
- 비공개 테스트의 새 출석 기록은 테스트용 세션에서 세션별 허용 목록에 직접 등록한 인증 사용자만 제출합니다. 4자리 숫자 코드를 DB에서 검증하며 시작 20분 전부터 종료 시각까지 양 끝을 포함해 받습니다. DB 요청 시각으로 판정하고 사용자·세션별 한 기록만 저장합니다. 완료된 요청의 재시도는 종료 뒤에도 원래 처리 시각을 반환하며 본인 기록만 재조회합니다. 시간 구간별 등급·점수와 미확정 YAPP 정책은 이 검증에 추가하지 않습니다.
- 테스트 종료 뒤 자동으로 데이터를 삭제하지 않습니다. 운영 데이터로의 전환은 수동으로 수행하며 실제 전환 시점·대상·절차는 후속 결정입니다.
- Supabase 인증 세션과 YAPP API 세션을 분리합니다. Google ID 토큰·원본 nonce는 교환 중 메모리에서만 사용하고 로그·영구 저장소에 남기지 않습니다. 앱에 Supabase secret/service-role 키를 포함하지 않으며 노출 데이터는 RLS와 최소 권한으로 제한합니다.
- Supabase Google provider 설정은 사용자가 열어 둔 Supabase Dashboard에서 컴퓨터 사용으로 적용합니다.

적용 상태: 인증·공지 Domain 계약과 공급자 교체 경계, [세션·공지·테스트 출석 migration](../../supabase/migrations/20261020093715_mvp_test_sessions_notices_attendance.sql), Supabase Auth DataSource·Repository의 암호화 세션 저장·복원 기반을 추가했습니다. migration은 실행 시점의 한국 시간 기준 이번 주·다음 주 토요일에 가상 세션과 공지를 만들며 모든 제목에 `[더미]`를 표시합니다. 표본 시각은 14:00–16:00, 장소와 공식 기수 정보는 비워 둡니다. 코드·허용 목록도 빈 상태라 관리자 설정 전에는 출석이 거절됩니다. 일정·공지 Supabase DataSource와 공지 Repository·App Hilt는 연결했습니다. 주간 일정은 서버의 일요일~토요일 범위에서 시작·종료 시각과 ID 순 첫 테스트 세션을 반환하고, 미설정 기수는 공식 기수가 아닌 테스트 전용 0으로 둡니다. 실제 Supabase 프로젝트 적용·테스터별 허용 등록·코드 설정, Login·공지 Feature와 출석 DataSource 연결은 후속입니다. 표본 일정은 공식 YAPP 일정이 아니며 관리자가 조정할 수 있습니다.

## 인증 화면 결정

앱 초기 화면에는 Google 로그인 버튼만 표시합니다. 회원가입 안내 문구·버튼과 이를 나누는 “또는” 구분선은 표시하지 않습니다. 이름·전화번호 입력과 승인·완료·문제 화면은 상태·콜백 기반 UI로 제공합니다. Google 버튼은 Credential Manager의 명시적 Google 로그인 흐름으로 Google ID 토큰과 요청 nonce를 받습니다. 토큰은 App 콜백으로 메모리에서 전달하며 로그·저장소에 남기지 않습니다. 현재 서버 계약에는 Google ID 토큰 검증과 YAPP 세션 발급 API가 없으므로 토큰 발급만으로 로그인·회원가입이 완료된 것으로 처리하지 않고 로그인 화면에 머뭅니다. ID 토큰은 서버 검증 전까지 신뢰할 수 없습니다. 앱의 데모 입력값은 뒤로 가기·구성 변경·시스템에 의한 상태 복원에서 유지하며, 입력 검증 없이 다음 버튼을 활성화합니다. 완료·문제 화면은 Preview에서만 제공합니다.

Google Auth Platform은 External/Testing으로 설정되어 있습니다. `com.yapp.plus`와 debug SHA-1을 가진 Android 클라이언트 및 Credential Manager의 ID 토큰 audience로 사용하는 Web 클라이언트를 등록했습니다. 테스트 사용자 목록에 포함된 계정만 이용할 수 있으며, 현재 release 서명 키가 없어 release SHA-1 클라이언트는 등록하지 않았습니다. 앱 공개 검증과 release용 서명 지문 등록은 별도입니다.

YAPP 세션이 공급된 뒤에는 인증된 API 요청의 401 응답에 refresh token으로 갱신을 시도하고 원래 요청을 한 번 재시도합니다. 동시에 발생한 갱신은 결과를 공유합니다. 최신 YAPP 토큰 쌍은 DataStore에 저장하고 재실행 시 복원하며 세션 삭제·갱신 거절도 저장에 반영합니다. Google ID 토큰과 nonce는 저장하지 않습니다. 갱신·저장 동작과 미구현 로그인 연동 범위는 [설계 패턴](design-patterns.md)을 따릅니다.

Notion의 가입 정책은 가입 코드가 있으면 코드에 연결된 역할을 부여해 가입하고, 코드가 없으면 가입 신청을 받아 운영진이 승인하거나 거절하는 흐름입니다. 활동 기수·직군 입력은 공란이 있으면 다음 단계로 진행할 수 없고, 기수는 숫자로 입력합니다. 가입 화면 사양은 PM, UXUI Design, Android, iOS, Web, Server를 직군 선택지로 두고 이전 활동 이력을 추가할 수 있게 하며, 중복 검사는 하지 않는다고 설명합니다. 이 입력 목록은 정관상 직군과 다르므로 실제 현재·이전 직군 값의 대응과 운영진의 복수 직군은 미정으로 남깁니다. 가입 API·코드 검증·운영진 처리 계약도 아직 정해지지 않았습니다.

## 메인 화면 데모

승인 대기 화면에는 “앱 둘러보기” 버튼을 표시하지 않으며, 가입 UI 데모는 승인 대기에서 끝납니다. 네 탭 화면은 캡처 편의를 위한 debug 홈 시작 경로로 확인하고, release 변형은 기존 로그인 진입 흐름을 유지합니다. 홈의 이번 주 세션 요약과 일정 목록은 세션 조회 API 응답을 표시합니다. 게시판·My의 데모 표시는 실제 회원 정보나 서버 확정 출석 결과를 의미하지 않습니다.

출석 기록 API가 준비될 때까지 홈에는 정적 출석 이력이나 데모 안내를 표시하지 않습니다. 홈 세션의 Preview 예시 값은 debug 전용 리소스에 둡니다. My의 기존 콘텐츠에는 데모 안내를 표시하고, 일정 화면의 고정 데모 데이터 안내는 상태 없는 Preview 경로에서만 표시합니다.

## 수정된 홈 화면과 연결 흐름

- 기준은 사용자가 변경을 확정한 [Figma 홈 섹션](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=222-40284)과 [이슈 #82](https://github.com/YAPP-admin/yapp-plus-android/issues/82)입니다. 홈 메인·알림·출석 코드 입력/완료·출결 보고 화면까지 적용합니다.
- 홈은 이번 주 세션의 장소·제목, 일요일부터 토요일까지의 달력, 출석 상태와 빠른 메뉴, 이번 주 공지를 표시합니다. 오늘은 원형으로, 세션 날짜는 브랜드 색상으로 구분합니다. 서버의 `AVAILABLE` 상태에서만 출석 버튼을 활성화합니다.
- 4자리 숫자 입력은 붙여넣기와 숫자 키보드를 지원합니다. 입력 형식 검증 뒤 `POST /api/attendance-verifications`에 `sessionId`와 정수 `code`를 전달합니다. `verified=true`와 유효한 `checkedInAt`을 받은 뒤에만 완료 화면과 해당 세션의 출석 완료 상태를 표시합니다. 조회 API에는 완료 상태가 없어 이 상태는 현재 ViewModel 생명주기 안에서만 유지합니다.
- 보고는 지각·조퇴·결석 선택 후 30자 이내의 공백 아닌 사유를 입력합니다. 서버의 `POST /api/attendance-reports`에는 `ONE_HOUR_LATE`, `THREE_HOUR_LATE`, `EARLY_LEAVE`, `ABSENT` 중 하나와 사유를 보냅니다. 응답의 `sessionId`·`submittedAt`을 확인한 뒤 완료 안내를 표시합니다. 서버의 허용 시간과 점수를 클라이언트에서 재판정하지 않습니다.
- Figma의 지각 한 항목과 서버의 1시간/3시간 구분 차이는 사용자 지시에 따라 지각 선택 뒤 추가 선택 단계로 우선 처리합니다. **디자이너 확인 전 임시 UI**이며, 일반 `LATE` 값은 서버가 거절하므로 보내지 않습니다.
- 알림과 일반 회원용 공지 조회 API는 2026-10-19 개발 서버 OpenAPI에 없습니다. 빈/목록 UI와 입력 모델을 제공하고 현재 App에는 빈 목록을 공급합니다. 실제 서버 조회·알림 읽음 처리는 후속이며 목록 예시는 debug Preview에만 둡니다.
- 전체 세션은 일정 탭, 출석 점수는 My 탭으로 연결합니다. My의 점수/기록 API는 아직 연결되지 않았으며 기존 데모를 실제 데이터로 표시하지 않습니다.
- API 실패 시 입력을 보존하고 오류·재시도를 제공합니다. 제출 중에는 중복 확인·입력 수정·시트 닫기를 막습니다. 코드 불일치와 일반 요청 실패를 구분하며 성공 상태를 낙관적으로 만들지 않습니다.

## 출석 인증과 사전 보고 API 계약

- `POST /api/attendance-verifications`는 `sessionId`와 정수 `code`를 받습니다. 서버 응답의 `verified`와 `checkedInAt`으로 검증 성공을 판정하며 출석의 최종 확정과 점수 계산은 서버가 담당합니다.
- `POST /api/attendance-reports`는 `ONE_HOUR_LATE`, `THREE_HOUR_LATE`, `EARLY_LEAVE`, `ABSENT` 중 하나와 사유를 받습니다. 응답의 `sessionId`와 `submittedAt`으로 서버의 제출 결과를 확인합니다.
- Domain은 출석 코드 검증·사전 보고 Repository 계약과 보고 종류·코드 오류 표현을 정의합니다. Data의 DTO·API 연결과 Feature 연결은 후속 PR입니다.

## 일정·출석 정책

### 세션과 출석 대상

세션은 운영진이 주최하는 공식 일정이며 특정 기수에 포함됩니다. 동시에 진행되는 세션 중 한 세션에만 참석할 수 있습니다. 정기 세션은 매주 토요일입니다. 세션의 출석 대상은 해당 세션의 기수 활동 기록이 있고, 앱 역할이 활동회원이며, 해당 세션의 대상으로 선택된 회원입니다.

출석 화면은 출석 권한이 있는 회원에게 출석 대상 중 가장 가까운 세션을 표시합니다. 출석은 세션 시작 20분 전부터 종료 시간까지 가능합니다. 새 기수에 참여하는 OB와 프로젝트에 참여하는 운영진을 출석 대상으로 볼지는 미정입니다.

### 출석 상태와 점수

| 상태 | 기준 | 기수 점수 |
| --- | --- | --- |
| 출석 | 세션 시작 20분 전부터 시작 10분 후까지 | 감점 없음 |
| 지각 | 시작 10분 후부터 시작 2시간 후까지 | 10점 감점 |
| 결석 | 지각 구간 이후의 출석 또는 무단 결석 | 20점 감점 |
| 미출석 | 출석 기록 없이 세션이 종료됨 | 결석과 같이 20점 감점 |
| 공결 | 경조사 등 특수 사유를 이사회가 심의해 인정, 기수별 최대 1회 | 감점 없음 |
| 조퇴 | 기준과 감점이 정해지지 않음 | 미정 |

출석 점수는 기수마다 100점에서 시작하고 기수가 끝나면 초기화합니다. 회원은 언제든 본인 점수를 확인할 수 있습니다. 70점 이상은 활동 기간 이수 기준이며, 40점 이하는 제적 심의 대상입니다. 이사회는 가점을 주거나 감점을 면제할 수 있으며, 기존 “지각 면제권”도 이 판단에 포함됩니다. 점수 합산은 100 − 10 × 지각 횟수 − 20 × (결석 + 미출석 횟수) + 이사회 가점·감점 면제 점수이며 공결은 감점하지 않습니다.

OB에게는 결석 허용 횟수를 전체 세션 수의 1/3로 계산해 소수점 이하를 버려 표시합니다. 이를 초과해 결석하면 해당 기수의 활동 자격을 즉시 잃고, 이후 이사회가 제적 여부를 심의합니다.

Notion 표에는 출석·지각·결석의 시간 구간이 제시되어 있지만 같은 문서가 10분 경계의 초 단위 판정과 지각 종료가 시작 후 2시간인지 2시간 10분인지 확인이 필요하다고 표시합니다. 이 경계는 확정 전까지 코드 판정에 적용하지 않습니다.

### 출석·일정 화면

- 홈 출석 버튼의 활성화 여부는 서버의 출석 UI 상태를 따릅니다. 시간 전에는 세션 날짜·시작 시각으로 안내하고, 출석 가능 상태에서 활성화합니다.
- 홈 코드 검증 성공 화면은 수정된 Figma의 “출석을 완료했어요!”를 표시합니다. 서버 검증 응답에 시간 구간별 판정 상태가 없어 기존 구간별 평가 문구는 아직 적용하지 않습니다. 시간 구간의 정책은 앞의 미확정 경계에 따릅니다.
- 홈의 이번 달 세션은 활성 기수에서 설정된 월의 세션만 시작일·시작 시간·종료일·종료 시간 오름차순으로 표시합니다. 종료된 세션은 오늘 날짜의 세션이라도 과거로 보고 흐리게 처리하고, 아직 끝나지 않은 당일 세션과 미래 세션을 구분합니다. 홈 진입 시 당일의 가장 가까운 예정 세션을 가운데에 표시합니다.
- 세션 일정은 활성 기수의 전체 세션을 표시합니다. 종료된 세션은 흐리게 하고 출석 정보를 표시하며, 오늘 세션은 강조하고, 미래 세션은 “예정” 칩으로 표시합니다. 종료 시간이 지났고 기록이 없으면 미출석(결석)으로 취급합니다.
- 오늘의 세션 화면은 활성 기수에서 오늘 진행하는 세션을 보여 주고 세션명·시작일·장소·시작 시간·종료 시간을 표시합니다. 하루 여러 세션 지원과 대체 정보 배치는 출처에서 개선안으로 표시되어 확정 범위에 넣지 않습니다.
- 월간 전체 일정에는 선택한 연·월의 일정을 표시합니다. 세션에는 이름·장소·시간·출석 상태를 표시합니다. 과거 일정은 흐리게, 오늘 일정은 강조합니다. 태스크와 기타 일정의 표현은 미정입니다.
- 최근 출석 현황과 출석 내역은 세션명·출석 처리 시각·상태를 표시합니다. 기록이 있는 세션과 기록 없이 끝난 세션을 포함하며, 기록이 있는 미래 세션도 나타날 수 있습니다. 종료 세션의 기록 없음은 결석(미출석)으로 표시합니다.
- 출석 내역에는 상태별 횟수와 총점을 표시합니다. 세션 현황에는 전체·남은 세션 수를 제공합니다. Notion의 진행률 식은 남은 세션 비율을 계산하는 것으로 보인다고 출처에서 확인을 요청했으므로 진행률 계산은 미정입니다.

## 기타 화면 정책

- My 화면은 이름, 앱 권한 역할, 최근 활동 이력(기수·직군)을 표시하고 출석 내역·이전 활동 내역·이용 문의·회원탈퇴 메뉴를 제공합니다. 이용 문의는 카카오톡 오픈 채팅방으로 이동합니다. 앱 회원탈퇴는 계정 삭제이며 동아리 탈퇴와 구분해 안내합니다.
- 공지사항은 운영 공지와 세션 공지로 나누고 유형별 필터와 날짜 내림차순 정렬을 제공합니다. 기수별 필터는 출처에서 개선안으로 표시해 확정 정책에 포함하지 않습니다.
- 설정의 알림은 앱 푸시 전체 설정이며 해제하면 푸시를 보내지 않습니다. 이용약관은 각 약관의 Notion 페이지로 연결하고 현재 앱 버전을 표시합니다.
- 이전 활동 이력은 기수·직군 조합이며 시작일과 종료일은 비어 있을 수 있습니다. 회원 용어와 공식 직군 범위는 [회원·역할 정책](membership-policy.md)을 따릅니다.
