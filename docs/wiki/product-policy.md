# 제품 정책

출석 기능의 동작은 확인된 요구사항과 API 계약을 기준으로 정합니다. 클라이언트가 보여주는 진행·예상 상태와 서버가 확정한 출석 결과를 구분합니다. 이 원칙은 출석 판정 기준이나 서버 응답 형식을 정한 것이 아닙니다.

## 인증 화면 결정

앱 초기 화면에는 카카오 로그인 버튼만 표시합니다. 회원가입 안내 문구·버튼과 이를 나누는 “또는” 구분선은 표시하지 않습니다. 이름·전화번호 입력과 승인·완료·문제 화면은 상태·콜백 기반 UI로 제공합니다. 승인된 카카오 버튼 → 이름 입력 → 휴대폰 번호 입력 → 운영진 승인 대기의 UI 데모 경로를 Navigation 2로 구현했습니다. 뒤로 가기는 승인 대기 → 휴대폰 번호 → 이름 → 로그인 순서이며 로그인에서 시스템 뒤로 가기는 Activity를 종료합니다. 데모 입력값은 뒤로 가기·구성 변경·시스템에 의한 상태 복원에서 유지하며, 입력 검증 없이 다음 버튼을 활성화합니다. 완료·문제 화면은 Preview에서만 제공합니다. 카카오 SDK·OAuth/API·토큰 및 실제 가입 서버 처리는 별도 인증 정책과 서버 계약이 정해진 뒤 연결합니다. 이 데모 흐름은 실제 인증·가입·운영진 승인 정책을 확정하지 않습니다.

## 아직 정해지지 않은 항목

| 항목 | 현재 상태 | 구현에 필요한 결정 |
| --- | --- | --- |
| 출석 판정 | 미확정 | 세션 식별, 시간·위치·코드 조건, 중복·지각·결석 처리 |
| 출석 API | 미확정 | 엔드포인트, 인증 방식, 요청·응답, 오류·재시도 계약 |
| 실제 인증 | 미확정 | 가입·로그인 API 계약과 토큰 관리 정책 |
| 로컬 저장 | 미확정 | 보존할 데이터와 기간, 동기화·삭제 규칙 |

미확정 항목을 임의의 클라이언트 규칙이나 DTO로 구현하지 않습니다. 정책이 확정되면 이 표를 갱신하고 실제 규칙을 이 문서에 기록하며 [결정 기록](decisions.md)을 추가합니다.
